PROMPT 17 of 26 - VFX WITH PURPOSE
Game: Tiny Boatball! (Roguelike or dungeon run, LOVE (Lua))
Rules this serves: 17 VFX with purpose

GOAL
Every effect has four layers (wind-up, main effect, impact, lingering trail) and each layer tells the player something. No effect just for looks. Particles are reused and overdraw is capped.

LOOK AT FIRST (read only, change nothing yet)
- [ALREADY IN THE GAME - check it works, do not rebuild] Every existing effect and particle. For each: what does it tell the player?
- Which effects cover the screen or stack on top of each other.
- Where particles are created, and whether they are reused.

BUILD (small steps, in this order)
1. List every effect in the memory file with the information it gives. Mark the ones that give none.
2. Remove or shrink effects that give no information.
3. For each important action, define the four layers. Wind-up: warns what is about to happen. Main effect: shows what is happening. Impact: shows the result. Lingering trail: shows where it was or what is left. Keep each layer short.
4. [ALREADY IN THE GAME - check it works, do not rebuild] Use ONE particle pool for the whole game with a fixed maximum, and reuse the particles. Nothing is created per frame.
5. Cap overdraw: limit how many big transparent effects can overlap, and fade the oldest first.
6. Make colors tell meaning (for example one color for danger and one for reward) and keep them consistent.
7. Add a "low effects" setting that cuts particles in half and removes the trails. Use it automatically on the weak phone if the frame rate drops.

DO NOT TOUCH
- Do not add effects without a reason. Every effect must say something.
- Do not make effects hide the player or the threat.
- Do not create particles per frame.
- Anything outside this prompt's goal. If you spot another problem, write it under "Seen but not fixed" in the memory file and leave it.
- These files and folders must never be edited (read them if you must, never write):
    toolkit/lib/
- Do not edit third-party library files.

DONE WHEN
- Every effect that remains tells the player something.
- The particle count never goes above the cap and nothing is created per frame.
- Low-effects mode keeps the weak phone smooth.

QUICK TEST (Run the folder with LOVE (love .).)
1. Trigger the busiest moment of the game on the weak phone with the debug view open. The frame rate must hold.
2. Turn low effects on and compare.
