PROMPT 12 of 26 - POINTER TUTORIAL
Game: Tiny Boatball! (Roguelike or dungeon run, LOVE (Lua))
Rules this serves: 1 Tutorial

GOAL
Teach with a pointer, not with text. A hand or pointer goes to each part of the game one by one and shows what it is, only when the player is curious. Never a wall of steps.

LOOK AT FIRST (read only, change nothing yet)
- The existing tutorial or hints, if any. List every text step. Those get replaced, one at a time.
- Every part of the screen the player needs to know about (controls, health or lives, goal, currency, key buttons).
- What "curious" means in this game: the player stopping, hovering or tapping near something, pausing, or failing at the same spot twice.

BUILD (small steps, in this order)
1. Build one tiny pointer component: a hand or arrow drawn from the game's own art, that moves to a target with the shared UI timing and gently pulses. Reuse one object, do not create it again each time.
2. Show ONE target at a time. Never queue steps. The pointer shows what the thing is with a small picture or motion, not a sentence.
3. Only trigger a pointer when the player is curious (they tapped near it, paused, or failed twice). Never interrupt play.
4. Never block the game. The pointer fades if the player ignores it, and any tap dismisses it.
5. Remember what the player has already been shown (put it in the save data, with a version) so nothing repeats.
6. Add a small "show me again" spot for each thing, near pause. It must not use words, only the thing's icon.
7. Remove or replace every old text tutorial step you listed.

DO NOT TOUCH
- Do not add tutorial text, popups or step counters.
- Do not show a pointer during a hard moment of play.
- Do not change controls or rules.
- Anything outside this prompt's goal. If you spot another problem, write it under "Seen but not fixed" in the memory file and leave it.
- These files and folders must never be edited (read them if you must, never write):
    toolkit/lib/
- Do not edit third-party library files.

DONE WHEN
- No text tutorial remains.
- Pointers appear one at a time, only when the player is curious, and never repeat.
- The pointer never blocks play.

QUICK TEST (Run the folder with LOVE (love .).)
1. Start a new game and just play. A pointer should show up only after you pause or hesitate.
2. Ignore a pointer. It should fade.
3. Restart the game. Seen pointers should not come back.
